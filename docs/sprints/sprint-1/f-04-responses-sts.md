# F-04 - Response Software Test Specification

Version 0.1, 2026-11-07. Paired [contract](f-04-responses.md), Issue #13, later implementation #20. Every case is **Planned / Not run**; current #15 tooling checks are unrelated to F-04 acceptance. There are 25 stable AC and 36 planned cases: 6 unit, 21 API/real DB, 4 selected browser, 3 dependent integrations and 2 supplementary/process checks. Parameterization may produce different actual runner counts.

Fixtures: isolated allowlisted PostgreSQL DB with reviewed #16 schema; real F-01 OWNER/RESPONDENT sessions/token jars; two owners/Sections of one Course, two eligible students, ineligible student, Draft/Published/Closed contexts, required/optional rating/text, controlled Unicode values and deterministic two-connection race barriers. Hashes/cookies/tokens/raw answer content are excluded from retained logs/screenshots. Fault injection/test clocks stay private to test composition, never public endpoints. Inspect actual row counts/typed values after every rejection/rollback, not just status codes.

Planned files after authorized implementation: `apps/api/tests/responses.unit.test.ts`, `apps/api/tests/responses.integration.test.ts`, `tests/e2e/responses.spec.ts`; these files do not exist from writing this STS. #15 defines actual runners; #20/#22/#23 later record real source/test names, command/date/environment/schema/lockfile, tested SHA, expected/observed result, pass/fail/skip counts and safe output. M checks remain separate from automated counts.
