## 1. Execution model and fixtures

Use provisional PR #29 naming: U = unit, I = HTTP/real-PostgreSQL integration, E = selected UI/E2E, M = supplementary/manual/process and H = dependent cross-feature integration. These are design IDs, not runner pass counts. Parameter matrices under one ID can become multiple executed cases; record actual counts separately. Commands and actual test paths are established by #15/#18, not invented here.

Tests use real F-01 login/session identity, actual F-02 HTTP routes and a separately allowlisted disposable PostgreSQL test database. A test-only injected actor is not authentication proof. Pure units can use controlled inputs; relationship/security claims require real DB assertions. Test composition may inject failures/barriers without adding public debug endpoints. Never reset development/deployed data or publish passwords, hashes, cookies, tokens or raw session JSON in output.

| Fixture | Required synthetic setup / meaning |
| --- | --- |
| O-A, O-B, O-EMPTY | Distinct OWNER Users; O-EMPTY owns no Sections. No real student/staff data. |
| R-A, R-B, R-NEW | Distinct RESPONDENT Users. R-A and R-B have different eligibility and participation; R-NEW can be added to Membership after publication. |
| C-SHARED, C-OTHER | Courses; Sections S-A and S-B in C-SHARED owned by O-A and O-B. O-A owns a Section in C-OTHER and S-EMPTY with no lectures. Multiple owned Sections in C-SHARED test Course deduplication. |
| L-A1, L-A2, L-B1, L-FREE | Lectures scoped to their Sections; L-A1/L-A2 share a date but have distinct sequences. L-FREE has no survey. Include Thai/English and markup-like metadata for rendering. |
| Q-DRAFT, Q-PUB, Q-CLOSED, Q-FOREIGN | Surveys on distinct lectures; own Draft/Published/Closed and another owner's survey. Published/Closed questions/eligibility match reviewed F-03 schema. R-A is eligible for Q-PUB/Q-CLOSED; Draft eligibility is absent under normal publication rules. |
| Participation | R-A has submitted Q-CLOSED but not Q-PUB; R-B can have participation in Q-PUB without making R-A submitted. Only eligibility-backed rows; real submissions tested in H02. |
| Pagination | Deterministic generated synthetic dataset exceeding 100 records; two owners' records interleaved in ordering. Use accepted #16 constraints, valid unique IDs/relationships and stable expected authorized IDs. |
| Snapshot/failure controls | Real DB connections plus barriers around the count/items read boundary and competing committed writes. Inject known dependency faults at private composition boundaries. No sleeps presented as concurrency proof. |

Fixture names are aliases, not production IDs. #16 generates actual canonical UUIDs; examples in documents are not executable seed output. Raw test fixtures may directly prepare valid reviewed database state for F-02 reads; that does not demonstrate implemented publication/submission. H01/H02 supply actual route-based product evidence later.
