## 2. Deterministic fixtures and execution setup

Use synthetic Owner A/B with separate Sections of the same Course, owned Lectures and unique Survey-per-Lecture fixtures in each state. Respondents have one role, and F-01 supplies real sessions. Seed an extra eligible but unsubmitted respondent to distinguish participation from enrollment. Published/Closed fixtures have the frozen definition and SurveyEligibility; membership changes afterward must not change result inputs. #16 owns schema/migrations/seed; test setup is isolated from another developer's DB and never a public endpoint.

**Fixture A (Closed IDENTIFIED):** seven eligible respondents, six committed Participation/identified bundles (R1–R6); R7 does not submit. Questions in order: Q1 required RATING clarity with explicit frozen anchors/interpretation; Q2 optional RATING pacing slow→fast (not “better”); Q3 optional TEXT suggestions. Q1 scores by R1…R6 are `[1,2,3,4,5,5]`: R=6, N=6, S=20, bins `[1,1,1,1,2]`, mean `"3.33"`. Q2 scores are `[2,omitted,omitted,4,omitted,5]`: N=3, S=11, bins `[0,1,0,1,1]`, mean `"3.67"`. Every response remains valid via Q1; omitted optional answers have no Answer row. A second Owner's survey has different counts and sentinel feedback `OTHER_OWNER_SECRET` to detect cross-survey reads.

Q3 comments: R1 = `<img src=x onerror="window.__f05Executed=true"><script>window.__f05Executed=true</script>`; R2 omitted; R3/R4 both `Same feedback`; R5 = `Line one\nLine two` (actual newline in persisted fixture); R6 = `ข้อเสนอแนะ`. Expected five strings in UTF-8 byte/C-collation order: the `<img...` string, multiline `Line one...`, two separate `Same feedback` strings, then Thai text. Preserve the malicious-looking literal text but never execute it. Add a second TEXT question in the privacy subfixture with different per-respondent order to prove the API has no bundle-aligned/correlated response object. No identity/timestamp is attached to strings.

**Fixture Z0:** valid Closed survey, nonempty eligibility, no submissions. All rating bins zero, means null, comments empty. **Fixture Z1:** valid Closed survey with required TEXT answered once and optional RATING omitted; R=1, rating N=0, mean null. Text-only response is valid because the published definition includes that optional RATING and the response contains nonempty TEXT. A Closed one-rating-response fixture proves no identified minimum-count suppression.

**Rounding fixtures:** T1 seven 1s and one 2 (N=8,S=9,1.125→`"1.13"`); T2 thirteen 2s and twenty-seven 3s (N=40,S=107,2.675→`"2.68"`); endpoints one score 1/5→`"1.00"`/`"5.00"`. Unit-only histograms below/above the tie use 219 ones/31 twos (281/250=1.124→`"1.12"`) and 437 ones/63 twos (563/500=1.126→`"1.13"`); no need to create hundreds of DB accounts for those unit assertions.

Run future integration against real migrated PostgreSQL, HTTP middleware and F-01 sessions; never substitute SQLite/in-memory mocks for SQL grouping/access/snapshot evidence. Use separate connections and explicit transaction barriers, not sleeps or request-start order, for race tests. Real browser/API/DB E2E proves persistence/rendering; mocked success alone cannot. Test-only instrumentation can observe statement classes/transaction points without logging query parameter values or raw comments. Failure injection is a private harness seam/controlled DB outage, not an application feature.

When executed, record actual file/test name, command, environment/database version, tested SHA, observed result, pass/fail/skip counts and safe artifact/reviewer links. Actual errors/skips remain visible. Documentation validation is separate from application results.
