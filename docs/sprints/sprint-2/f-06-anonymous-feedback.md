## Design and workflow

- A survey owner sets the Draft mode with the existing revision-checked definition update. Published and Closed definitions remain frozen. Show the mode in both roles before response entry. The anonymous notice explains account-based eligibility and once-only participation, status-only readback and exposure risks from infrastructure observation or external information.
- Approved OPEN-04 policy: reject anonymous TEXT at the definition, publication and submission boundaries. Identified surveys still support written feedback. Validate the full Draft before publishing and reject a TEXT question in anonymous mode. An owner can remove text or select identified mode. Reject a forged text submission before writing. Existing identified drafts and surveys keep their data and UI.
- Within the existing survey-locked submit transaction, insert the eligibility-linked participation and exactly one answer bundle. For anonymous mode the bundle identifier is independently random, has no student, session, participation identifier or precise submission timestamp, and is not returned to the student. The database retains a unique student/survey participation key. Reads never correlate participation and bundles. Keep identity-vs-mode constraints at the write boundary and in SQL. Inspect storage and application logs as part of verification. Infrastructure, backups and timing remain outside the stated anonymity guarantee.
- An eligible respondent receives HTTP 200 with exactly `{ "data": { "surveyId": "<survey id>", "submitted": false } }` from GET /api/surveys/:id/my-submission before submission. After submission it returns the same shape with `submitted: true`, including after closure and relogin. Successful anonymous POST /api/surveys/:id/responses returns HTTP 201 and that same submitted-true shape. Omit answers, bundle ID, timestamps and correlation tokens altogether. Read status only from Participation.
- The owner-visible survey-level response count remains visible in both Published and Closed states and counts committed submissions. Published results return count and context only. Closed results evaluate RATING and SINGLE_CHOICE questions independently. Release requires at least five valid answers for that question and at least three answers in each nonzero bin. A suppressed question returns frozen question metadata and a generic suppression status. Omit answered count, mean and the complete distribution. CSV and trends consume the same per-question release decision.
- The 5/3 thresholds are disclosure controls. A concentrated result, repeated observations, external knowledge or privileged infrastructure access can still permit inference. The disclosure makes these limits clear.
- The schema migration is additive for existing identified records. Owner/respondent role checks and authorization for scope occur before a result can be returned. Maintain safe 404 for out-of-scope records, 409 for stale state or duplicates and 422 for invalid definitions or answers. Failed and duplicate writes do not create extra rows.
